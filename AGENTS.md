# AGENTS.md

Instructions for AI coding agents working in this repo. `README.md` explains what the app does and how the code is laid out.

## Ground rules

- Don't invent facts, APIs or library behaviour. When you're unsure, say so.
- Explain trade-offs when you choose an approach.
- Only claim to have run, built or tested what you actually ran. Say what wasn't tested.

## Build and test

```sh
cargo build --target wasm32-unknown-unknown   # frontend type-check, fast
cd src-tauri && cargo build && cargo test --lib
cd .. && cargo tauri build --debug            # full app bundle
cargo check --target x86_64-pc-windows-gnu      # in src-tauri: Windows type-check (needs the target; CI builds it for real)
```

fsd searches are the `fsd` cargo feature. `cargo tauri dev` and `cargo tauri build` turn it on (`build.features` in `tauri.conf.json`); plain `cargo build` and `cargo test --lib` leave it off, so add `--features fsd` there to build and test them. Keep both ways building without warnings.

The bundle carries fsd as `ferry-fsd`, built by the bundle step (`beforeBundleCommand` in each `tauri.<os>.conf.json`, `cargo install … --root src-tauri/libs/fsd`) and added with `macOS.files`, the Linux packages' `files`, and a Windows resource folder, none of which tauri-build checks, so plain `cargo build` needs no fsd. Don't make it an `externalBin`: tauri-build would then refuse to build without it. Settings > Search (`fsd_service.rs`, `app/fsd.rs`) installs it with fsd's own `install-service`, and only ever changes the service it installed: the one started with Ferry's config in `platform::fsd_dir()`.

Ferry talks to fsd with the `fs-protocol` crate's client (`src-tauri/src/fsd.rs`), and depends on no other fs crate. Anything under `fs/` follows `fs/CLAUDE.md`. A change to fs's `ipc_protocol.rs` bumps its `PROTOCOL_VERSION` and must keep Ferry building and its `--features fsd` tests passing in the same change. An fsd installed separately can speak another version, so `fsd.rs` keeps its plain message for that ("update the older one").

Rust code is formatted with rustfmt (`rustfmt.toml`, for both crates): run `cargo fmt` in the root and in `src-tauri`. The pre-commit hook in `.githooks/` formats the staged Rust files; turn it on once per clone with `git config core.hooksPath .githooks`.

Keep builds free of warnings. If an `rtk` hook filters command output, use `rtk proxy cargo …` to see the raw compiler output.

Phone tests (`cargo run --example smoke` and `--example epub_smoke`) need a connected phone, and nothing else may be holding MTP, this app included. Before quitting a running copy of the app, check that it isn't the user's own session.

## Rules for changes

- **User data comes first.** Every write to the phone goes through `Device::write` and `Device::remove`, which check the version and make a backup. Never bypass them. The only deletes without a backup are on the computer: the Trash (`Device::trash`) and Delete permanently (`Device::remove_forever`), which the user picks by name; phones and servers never get them. Tests and experiments must work on scratch copies (as `epub_smoke` does), never on the user's real files, and must clean up afterwards.
- **EPUB edits splice the original text.** `src-tauri/src/books/epub.rs` edits by byte ranges from `books/xml.rs` tokens, so untouched markup keeps its exact bytes. Don't re-serialize whole documents with a DOM library. Validate edited XHTML/OPF with `xml::check` before storing it, and write error messages in plain language that name the line.
- **Adding a Tauri command** means updating four places:
  1. the function in the fitting module (`files.rs`, `transfer.rs`, …), with `#[tauri::command(rename_all = "snake_case")]`;
  2. `generate_handler!` in `src-tauri/src/lib.rs`, as `module::name` (`group::module::name` for modules in `books/`, `devices/`, `preview/` and `servers/`);
  3. the command list in `src-tauri/build.rs`;
  4. the `allow-…` permission in `src-tauri/capabilities/default.json`.

  Mirror any new types in `src/api.rs`. The files in `src-tauri/permissions/autogenerated/` are written by the build and not committed.
- **Slow device or zip work** runs inside the `blocking()` helper (`spawn_blocking`), so the UI thread stays free.
- **libmtp** is loaded at runtime with libloading, using hand-written struct layouts for libmtp 1.1.x on 64-bit macOS and Linux. Check the libmtp headers before changing them. On Windows, `devices/wpd.rs` is compiled as the `mtp` module instead and must keep the same API (`detect`, `Detected`, `Mtp::open`, `stop_copies`, `MTP_HINT`).
- **PDFium** is loaded at runtime (`preview/pdfium.rs`, `pdfium-render` with the `pdfium_8125` bindings), from the bundle or `src-tauri/libs/pdfium` (`scripts/fetch-pdfium.sh`). Keep the script's version and the cargo feature in step. It is the only PDF reader in the app (lopdf is a dev-dependency, for building test PDFs). Without it the PDF preview falls back to the web view's viewer with no outline, search or text, so the rest of the app must not require it. Pages are served as raw RGBA by `ferry://…/pdfpage` (an 8-byte width and height first) and put on a canvas; a PNG took longer to encode and decode than PDFium took to draw. The last two PDFs opened stay open (`pdfium::doc`), so a page doesn't parse the file again. The frontend (`app/pdf.rs`) draws each near page rough first (`ROUGH_PX` across), then sharp only the pages in view once scrolling stops, two requests at a time; zoomed in past about three screens of pixels, only the piece in view is drawn (`&t=x,y,w,h`, in the unturned page's pixels). Keep what's held to about a screen's worth: pages out of view drop their sharp canvas. Zoom, turn and resize keep the reader's place by page and fraction (`anchor` in `PdfView`), not by scroll fraction. `pdf_find`, `pdf_marks` and `pdf_text` read the same PDFium text, so the matches listed are the ones marked and the text selected is the text searched. `pdf_text` also gives the page's links: page links go to their page, and only http, https and mailto addresses reach `open_link` (`pdfium::openable`).
- **Platforms**: OS differences go in `src-tauri/src/platform.rs` (backend) and `src/os.rs` (frontend), not scattered `cfg`s. The computer's paths are app paths everywhere ("/C:/Users" on Windows); convert with `platform::native`/`app_path` only where the file system is touched. UI text names the computer with `os::the_computer()` etc. and writes shortcuts as on the Mac, wrapped in `os::keys`.
- **The visual chapter view** is an `<iframe sandbox="allow-same-origin" srcdoc=…>`. Never add `allow-scripts`, because book scripts would then run next to the app's commands. The frontend serializes the body with `XMLSerializer` and sends it to `epub_set_body`.
- **Scripts** (`src-tauri/src/scripts.rs`) get only the `ferry` table and Lua's string, table, math, utf8 and coroutine libraries. Don't give them `io`, `os`, `package` or `debug`: their writes must go through `Device`, like everything else.
- **The EPUB editor is Rust only.** Don't bring back a JavaScript editor.
- **Frontend state** lives in `Copy` structs of signals (`Ctx` in `app.rs`, methods spread over `app/`, `Ep` in `epub.rs`). Get contexts while a component is being created, not inside event handlers. Book actions go through `Ep::act`, which commits the open chapter first.
- **UI text** is plain, short and specific: say what happened and what to do next. Styles use the CSS tokens in `styles/base.css` and support both light and dark mode.
- **Buttons show icons**, from `src/app/icons.rs` with `ico(Icon::…)`, and say what they do in both `title` and `aria-label`. Add a 16×16 line drawing there when none fits. Use words only when no picture is clear (Save as…, a dialog's Cancel and OK) or the label is a value (a zoom percentage).
- `target/`, `dist/`, `src-tauri/gen/` and `src-tauri/libs/` are build outputs and aren't committed.
